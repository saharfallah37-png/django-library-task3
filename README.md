# مدیریت کتابخانه با Django — تمرین ۳

این پروژه نسخهٔ وب یک برنامهٔ مدیریت کتابخانه است.
اطلاعات در لیست‌ها و دیکشنری‌های پایتون نگهداری می‌شوند
و پروژه از پایگاه داده و Django ORM استفاده نمی‌کند.

## امکانات

- نمایش فهرست کتاب‌ها و وضعیت موجود بودن آن‌ها
- جست‌وجوی کتاب با عنوان یا نام نویسنده
- نمایش فهرست اعضا
- ثبت امانت کتاب برای عضو
- جلوگیری از امانت دادن دوبارهٔ کتابِ در امانت
- بازگرداندن کتاب و ثبت تاریخ بازگشت
- نمایش سابقهٔ امانت هر عضو
- جداسازی امانت‌های فعال و بازگردانده‌شده
- نمایش آمار کتابخانه و محبوب‌ترین کتاب

## ساختار پروژه

- `config/`: تنظیمات و مسیرهای اصلی پروژه
- `library/sample_data.py`: کتاب‌ها، اعضا و سوابق نمونه
- `library/views.py`: منطق نمایش صفحات و عملیات امانت
- `library/urls.py`: مسیرهای برنامه
- `library/templates/library/`: قالب‌های HTML
- `requirements.txt`: وابستگی‌ها و نسخه‌های آن‌ها

## اجرای پروژه در GitHub Codespaces یا Linux

دستورها را در پوشه‌ای اجرا کنید که فایل manage.py قرار دارد.

### ایجاد و فعال‌سازی محیط مجازی

```bash
python -m venv .venv
source .venv/bin/activate
```

### نصب وابستگی‌ها

```bash
python -m pip install -r requirements.txt
```

### بررسی تنظیمات پروژه

```bash
python manage.py check
```

### اجرای سرور توسعه

```bash
python manage.py runserver 0.0.0.0:8000
```

در Codespaces از قسمت Ports، پورت 8000 را باز کنید
و گزینهٔ Open in Browser را انتخاب کنید.

در اجرای محلی، آدرس زیر را در مرورگر باز کنید:

http://127.0.0.1:8000/

## اجرای پروژه در Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

## مسیرهای اصلی

| مسیر | کاربرد |
|---|---|
| `/` | صفحهٔ اصلی |
| `/books/` | نمایش و جست‌وجوی کتاب‌ها |
| `/members/` | فهرست اعضا |
| `/borrow/` | فرم امانت کتاب |
| `/return/<book_id>/` | ثبت بازگشت با درخواست POST |
| `/history/<member_id>/` | سابقهٔ امانت عضو |
| `/statistics/` | آمار کتابخانه |

## نحوهٔ نگهداری اطلاعات

اطلاعات اولیه در فایل library/sample_data.py قرار دارد.

تغییرات هنگام اجرای برنامه فقط در حافظه نگهداری می‌شوند.
با راه‌اندازی مجدد سرور یا بارگذاری مجدد کد،
داده‌ها به حالت نمونه برمی‌گردند.

این رفتار مطابق محدودهٔ تمرین است.
برای اجرای این نسخه نیازی به migrate یا ساخت کاربر admin نیست.

این برنامه برای تمرین و اجرای توسعه طراحی شده است؛
ذخیره‌سازی پایدار و اجرای چندپردازشی در محدودهٔ آن نیست.

## بررسی دستی عملکرد

1. جست‌وجوی Python باید کتاب Python Crash Course را نمایش دهد.
2. جست‌وجوی Robert باید کتاب Clean Code را نمایش دهد.
3. عبارت ناموجود باید پیام نبود نتیجه را نشان دهد.
4. پس از ثبت امانت، وضعیت کتاب باید «در امانت» شود.
5. کتاب در امانت نباید در گزینه‌های فرم امانت باشد.
6. پس از بازگشت، وضعیت کتاب باید «موجود» شود.
7. سابقهٔ عضو باید عنوان کتاب و تاریخ‌های مربوط را نمایش دهد.
8. آمار موجودی و امانت باید پس از عملیات تغییر کند.

آزمایش امانت و بازگشت را بدون تغییر کد یا راه‌اندازی مجدد
سرور بین مراحل انجام دهید.

## نکات پیاده‌سازی

- جست‌وجو با GET انجام می‌شود.
- ثبت امانت و بازگشت با POST انجام می‌شود.
- فرم‌های POST شامل csrf_token هستند.
- قالب‌ها از base.html ارث‌بری می‌کنند.
- در تنظیمات این نسخه، کلید محرمانه از متغیر محیطی
  DJANGO_SECRET_KEY خوانده می‌شود؛ در نبود آن، یک کلید
  موقت هنگام اجرا تولید می‌شود.
